# V25.3e internal game finalization

Depends on V25.3d's durable session journal and the V25.3a settlement schema. Finalizer accepts only an internal match ID; it reconstructs a terminal game from the private journal, checks identity and revision, writes immutable final scores with a conditional update, then invokes the existing atomic Elo ledger. These are two recoverable phases, not a single transaction across both phases. If the second phase fails, retry the same match ID; neither player is partially updated and the completed score remains available. Duplicate and concurrent calls use the unique settlement record. Active sessions remain pending; void sessions never settle. No public HTTP route, no queue, no new database migration. A trusted authenticated boundary, authoritative admission, timeout scheduling, disconnect/forfeit policy, rate limits and real D1 Preview validation are still required. An operational retry/reconciliation caller is not implemented yet. Keep ranked disabled and do not migrate production.
