# V25.4b – internal bilateral match admission

Migration order: ranked-schema.sql, ranked-settlement-schema.sql, ranked-session-schema.sql, ranked-matchmaking-schema.sql, ranked-acceptance-schema.sql. The matchmaker now requires all five. Reservation creates a pending offer and active match in one SQL statement; the prior busy/queue triggers still apply. Both participants independently accept within 20 seconds of server reservation. A decline or expiry voids the reservation with no Elo settlement. Expiry runs on queue and offer operations; automatic background cleanup remains unimplemented. The trusted admission start method requires bilateral acceptance and atomically stores the initial presence monitor with the session. It is idempotent while the match is active. No UI, public auth route, automatic client transition, transport or production deployment. Accepted-but-never-started reservations still require a recovery/expiry policy before live use. Do not apply production migrations yet. The old internal direct session start is preserved for existing tests; the new schema blocks session insertion for pending/closed offers. Future public endpoints must exclusively use verified UIDs and the admission service, not raw internal functions. Run all Node 22.13+ tests without skips, then validate real D1 Preview separately.
