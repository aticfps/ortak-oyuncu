# V25.3d internal durable session prototype

The new migration follows ranked-schema.sql and ranked-settlement-schema.sql. Do not apply it to production yet. The service stores a versioned private seeded command journal; each state-changing command increments the revision using a conditional SQL update. Reconstructing a game from the journal retains its pairs, cooldowns, scores and terminal result. Duplicate persisted command IDs are idempotent; no-op commands are intentionally not recorded. Match/participant identity must be supplied by a trusted authenticated boundary, and tick commands are internal only. No public API or UI integration, no settlement writes and no automatic background timer. Match creation, verified disconnect/forfeit rules, server request authentication, rate limiting, terminal commit integration and real D1 Preview validation are still required. The deterministic RNG is for replay, not cryptographic proof or protection against clients who know the seed; never expose it. Keep the pinned catalog and game rules stable for this session version. Existing session migration would be required if their behavior changes. SQLite tests use Node 22.13+; run all tests with no skips.
